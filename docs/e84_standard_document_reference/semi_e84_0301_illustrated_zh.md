## 1 目的

**1.1** 随着晶圆尺寸向大直径迁移，未来的半导体工厂将广泛采用自动化物料搬运系统（AMHS）来搬运晶圆载具（包括 FOUP 与开放式晶圆盒），且载具重量不断增加。因此，生产设备与 AMHS 之间的并行输入/输出（PI/O）控制信号必须被更明确地定义，才能在生产设备的载口处实现更可靠、更高效的载具交接（装载/卸载）。

**1.2** 本规范的目的是增强 SEMI E23 所定义的并行 I/O 接口的能力，以支撑载具传输可靠性与效率的提升。所增强的能力包括：连续交接（continuous handoff）、同时交接（simultaneous handoff），以及接口上的错误检测能力。

> **注 1**：本文档中的规范应视为独立于 SEMI E23 的规范；因此，使用本规范并不要求使用 SEMI E23。

## 2 范围

**2.1** 本规范的范围限于主动设备与被动设备之间、与物料交接操作相关的通信。

- **主动设备**（active equipment）：例如 AMHS 设备，包括 AGV、RGV 与 OHT。
- **被动设备**（passive equipment）：例如生产设备，包括工艺设备、量测设备、储料机（stocker）等。

本范围还延伸至跨区（interbay）AMHS 场景下的主动设备（即 OHS，以及装有传输机构的储料机）与被动设备（即 OHS，以及未装传输机构的储料机）。本规范定义了用于在载具于生产设备与 AMHS 之间交接的增强并行 I/O 接口信号。图 1 与图 2 给出了各类 AMHS 设备的示例。

**2.2** 本增强载具交接并行 I/O 接口规范包括：

- 信号定义，含载口指定信号（见 6.1 节）；
- 载具交接时序定义与时序图（见 6.2 节）；
- 错误指示、检测与恢复（见 6.3 与 6.4 节）；
- 连接器类型、信号与引脚分配（见 6.4 节）；
- 位于载口处的接口传感器单元尺寸，由 SEMI E15.1 定义（适用于设计用于处理 300 mm 晶圆载具的系统）。

**2.3** 本增强载具交接并行 I/O 接口控制主动设备向被动设备交接载具、以及从被动设备取走载具的过程。该并行 I/O 接口**仅**控制载具的自动交接动作。交接是指载具从一台设备转移到另一台设备的操作。该操作由主动设备与被动设备**共同**管理；工厂级控制器（即主机 host）不管理交接操作。图 3 给出了本文档所规定并行 I/O 接口的应用示例。

## 3 限制

**3.1** 被交接物料的**数据**由设备的工厂接口（factory interface）管理。工厂级控制器对物料的管理不在本文档范围之内。

**3.2** 本规范定义了用于选择载口的信号，但**并行 I/O 接口与载口之间的物理对应关系**不在本文档中定义。

**3.3** 错误恢复流程可能需要操作员介入，和/或设备专有的私有流程。因此，错误恢复流程不在本文档中定义。

**3.4** 信号时序图仅适用于**一个**并行 I/O 接口。

**3.5** 并行 I/O 接口以及主动侧、被动侧连接器的**安装位置**未作定义。

**3.6** 对跨区 AMHS 设备（即 OHS、储料机）而言，**交换式交接（swap handoff）** 被视为超出本标准范围。交换式交接是指在同一载口上同时发生装载与卸载。

> ※ 译者注：3.6 这一条很关键——同一载口"先卸后装"必须走 6.2.4 的连续交接（Unload → Load）序列，而不是"同时装又卸"。

## 5 术语

| 编号 | 术语 | 定义 |
|---|---|---|
| 5.1 | **访问模式**（access mode） | 被动设备据以知晓哪一台 AMHS 设备（即 RGV、AGV、OHT/OHV）或哪位操作员被允许进行物料交接的模式。 |
| 5.2 | **主动设备**（active equipment） | 将晶圆盒装载到另一台设备的载具台上、或从另一台设备的载具台上卸下晶圆盒的设备 [SEMI E23]。 |
| 5.3 | **自动化物料搬运系统设备**（AMHS equipment） | 配有载具传输机器人、可在被动设备之间来回传输载具的设备。包括有轨导引车（RGV）、自动导引车（AGV）、空中吊运车（OHT）以及储料机。 |
| 5.4 | **自动访问模式**（automatic access mode） | 由 AMHS 设备（而非操作员）执行物料交接的模式。 |
| 5.5 | **载具**（carrier） | 任何装纳晶圆的晶圆盒、盒体、舱或 FOUP [SEMI E1.9]。亦称晶圆载具（wafer carrier）。 |
| 5.6 | **晶圆盒**（cassette） | 用于承载一片或多片基板的开放式结构 [SEMI E1.9]。亦称 open cassette（OC）。 |
| 5.7 | **连续交接**（continuous handoff） | 两个载具的相继交接。连续交接是**串行**的，即一次载具传输完成后立即接着下一次。连续交接可能涉及：装—装、卸—卸、或卸—装。 |
| 5.8 | **前开式统一舱**（FOUP） | 带不可拆卸晶圆盒（故其内部符合 SEMI E1.9）且带前开式接口（FIMS）的盒体（符合 SEMI E47.1）[SEMI E47.1]。 |
| 5.9 | **交接**（handoff） | 载具从一台设备转移（装载或卸载）到另一台设备的操作。 |
| 5.10 | **交接干涉区**（handoff conflict area） | 在交接操作期间，主动设备的运动机构可能与被动设备的运动机构发生干涉的区域。 |
| 5.11 | **交接互锁异常**（handoff interlock abnormal） | 一种状态，表示被动设备在交接操作中检测到异常条件；它可能意味着主动设备机构与被动设备机构已在交接干涉区内发生干涉。 |
| 5.12 | **交接不可用**（handoff unavailable） | 一种状态，表示被动设备当前不可用于物料交接操作。 |
| 5.13 | **载口**（load port） | 设备上放置晶圆载具以便设备处理晶圆的接口位置 [SEMI E15]。 |
| 5.14 | **手动访问模式**（manual access mode） | 由操作员（而非 AMHS 设备）执行载具物料交接的访问模式。 |
| 5.15 | **被动设备**（passive equipment） | 被主动设备装载或卸载的设备 [SEMI E23]。被动设备包括工艺设备、量测设备、储料机等。 |
| 5.16 | **同时交接**（simultaneous handoff） | 两个载具的**并发**交接操作。同时交接是**并行**的，即两个载具在同一时刻被传输。 |
| 5.17 | **单臂双手 AMHS 设备** | 使用单臂机构、带两只手（双末端执行器）来交接两个载具的 AMHS 设备。 |
| 5.18 | **单臂单手 AMHS 设备** | 使用单臂机构、带一只手（单末端执行器）来交接一个载具的 AMHS 设备。 |
| 5.19 | **单次交接**（single handoff） | 在一次交接操作中传输单个载具。 |

## 6 增强载具交接并行 I/O 接口要求

### 6.1 信号定义

**6.1.1** 表 1 给出了增强载具交接并行 I/O 接口所需的信号。该表定义了信号名、信息方向（P/A：**P** 代表被动设备，**A** 代表主动设备）以及说明。说明中给出信号的含义、信号电平的指示以及注释。

表 1 所定义的信号如下：

| 信号 | 全称 | 含义 |
|---|---|---|
| `VALID` | Valid | 表示信号跳变有效且已被选中 |
| `CS_0` | Carrier Stage 0 | 载具台位 0（载口选择） |
| `CS_1` | Carrier Stage 1 | 载具台位 1（载口选择） |
| `TR_REQ` | Transfer Request | 传输请求 |
| `L_REQ` | Load Request | 装载请求 |
| `U_REQ` | Unload Request | 卸载请求 |
| `READY` | READY for Transfer | 已就绪，可传输 |
| `BUSY` | BUSY for Transfer | 传输进行中 |
| `COMPT` | Complete Transfer | 传输完成 |
| `CONT` | Continuous Handoff | 连续交接 |
| `HO_AVBL` | Handoff Available | 可交接 |
| `ES` | Emergency Stop | 紧急停止 |
| `VA` | Vehicle arrived | 车辆已到达 |
| `AM_AVBL` | Transfer Arm Available | 传输臂可用 |
| `VS_0` | Carrier Stage 0 from Passive OHS Vehicle | 被动 OHS 车辆的载具台位 0 |
| `VS_1` | Carrier Stage 1 from Passive OHS Vehicle | 被动 OHS 车辆的载具台位 1 |

#### 表 1　增强载具交接并行 I/O 接口信号

| 信号名 | 方向 P/A | 说明 |
|---|---|---|
| **`VALID`** | A → P | 表示接口通信有效。 <br>ON：通信有效<br>OFF：通信无效<br>在本信号被置 ON 之前，必须先由 `CS_0` 和/或 `CS_1` 信号指定载口。 |
| **`CS_0`** | A → P | 指定用于载具交接的载口（见 6.1.2 载口指定信号）。<br>**一个 PI/O 对应一个载口**<br>　ON：使用该载口进行载具交接<br>　OFF：不适用<br>**一个 PI/O 对应两个载口**<br>　ON：使用**左**载口进行交接<br>　OFF：不使用左载口进行交接 |
| **`CS_1`** | A → P | 指定用于载具交接的载口（见 6.1.2 载口指定信号）。<br>**一个 PI/O 对应一个载口**<br>　不使用（恒为 OFF）<br>**一个 PI/O 对应两个载口**<br>　ON：使用**右**载口进行交接<br>　OFF：不使用右载口进行交接 |
| **`TR_REQ`** | A → P | 向被动设备请求交接。<br>ON：主动设备已请求交接<br>OFF：主动设备未请求交接<br>当 `BUSY` 信号跳变为 OFF 时，本信号被置 OFF。 |
| **`L_REQ`** | P → A | 表示该载口被指派为**装载**载具。`L_REQ` 始终表示载具由**主动侧向被动侧**传输。<br>ON：该载口被指派装载载具<br>OFF：该载口未被指派装载载具<br>当载口由 `CS_0` 和/或 `CS_1` 指定且 `VALID` 被置 ON 时，本信号置 ON。当该载口检测到载具位于正确位置时，本信号置 OFF。<br>在同时交接中，本信号置 ON 时两个载口上都不应存在载具；本信号置 OFF 时，两个载口上均应存在位于正确位置的载具。 |
| **`U_REQ`** | P → A | 表示该载口被指派为**卸载**载具。`U_REQ` 始终表示载具由**被动侧向主动侧**传输。<br>ON：该载口被指派卸载载具<br>OFF：该载口未被指派卸载载具<br>当载口由 `CS_0` 和/或 `CS_1` 指定且 `VALID` 被置 ON 时，本信号置 ON。当载口上的载具被取走时，本信号置 OFF。<br>在同时交接中，本信号置 ON 时两个载口上均应存在位于正确位置的载具；本信号置 OFF 时，两个载口上均不应存在载具。 |
| **`READY`** | P → A | 表示被动设备已接受主动设备的传输请求。<br>ON：被动设备已就绪，可交接<br>OFF：被动设备未就绪，不可交接<br>当被动设备接受传输请求时本信号置 ON；当 `COMPT` 信号置 ON 时本信号置 OFF。 |
| **`BUSY`** | A → P | 表示主动设备正在执行交接。<br>ON：交接进行中<br>OFF：无交接进行中<br>当主动设备开始交接操作时本信号置 ON。`BUSY` 置 ON 时 `READY` 必须为 ON。在主动设备完成交接、且其运动机构已移出交接干涉区之后，本信号必须置 OFF。**只要本信号为 ON，被动设备就不应在交接干涉区内执行任何机械动作。** 主动设备在确认 `L_REQ` 或 `U_REQ` 为 OFF 之后，才将 `BUSY` 置 OFF。 |
| **`COMPT`** | A → P | 表示主动设备已完成交接操作。<br>ON：交接已完成<br>OFF：交接未完成<br>当主动设备完成交接（`BUSY` 为 OFF）时本信号置 ON；在被动设备完成交接操作（`READY` 为 OFF）之后，本信号置 OFF。 |
| **`CONT`** | A → P | 指明本次交接为连续交接。<br>ON：连续交接<br>OFF：非连续交接<br>本信号在**第一个**载具交接的 `BUSY` 置 ON 时置 ON；在**最后一个**载具交接操作的 `BUSY` 置 ON 时置 OFF。<br>若被动设备存在会干涉交接的机构（如闸门 shutter door），则在连续交接期间该机构必须保持在非干涉状态（闸门必须保持开启）。 |
| **`HO_AVBL`** | P → A | 表示被动设备不可进行交接操作；也可能表示被动设备存在错误。<br>ON：可交接<br>OFF：因任何错误而不可交接<br>被动设备正常运行时本信号为 ON。当被动设备在由 `CS_0` 和/或 `CS_1` 指定的载口处检测到异常时，本信号因 `VALID` ON 或 `TR_REQ` ON 而被置 OFF。当被动设备的**其他**载口检测到异常时，本信号也可能被保持为 OFF。异常包括：<br>　- 载具检测不正确；<br>　- 被动设备已切换到手动访问模式；<br>　- 被动设备处于交接不可用状态。<br>本信号在交接操作开始之前向主动设备指示被动设备的状态。<br>关于载口访问模式与可用性状态的更多信息与要求，参见 SEMI E87。 |
| **`ES`** | P → A | 请求立即停止主动设备的动作。<br>ON：正常运行<br>OFF：请求停止（**注意为低有效**）<br>通常情况下，主动设备可以在 `VALID` ON 到 `VALID` OFF 期间监视 `ES` 信号。<br>当被动设备检测到危险状况时，本信号被置 OFF，以立即停止交接操作。危险状况包括可能对物料、产品或操作造成伤害的情形。被动设备正常运行时本信号为 ON；当被动设备需要停止主动设备的动作时它转为 OFF。被动设备可以在按下 `ES` 按钮时、或发生交接互锁异常时，将 `ES` 信号拉低。 |
| **`VA`** | P → A | 通知主动端：被动 OHS 车辆已到达。<br>表示车辆已到达载口时接口通信有效。<br>ON：车辆已到达，通信有效<br>OFF：车辆未到达，通信无效<br>在本信号置 ON 之前，必须先由 `VS_0` 和/或 `VS_1` 信号指定载口。<br>**注：本信号仅用于跨区被动 OHS 车辆。** |
| **`AM_AVBL`** | A → P | 通知被动 OHS 车辆：搬运臂可用。 |
| **`VS_0`** | P → A | 被动 OHS 车辆用于向主动端通报装载或卸载位置的信号。指定用于载具交接的载口。<br>**一个 PI/O 对应一个载口**<br>　ON：使用该载口进行载具交接<br>　OFF：不适用<br>**一个 PI/O 对应两个载口**<br>　ON：使用**左**载口进行交接<br>　OFF：不使用左载口进行交接<br>**注：本信号仅用于跨区被动 OHS 车辆。** |

### 6.2 载具交接时序

**6.2.1** 符合本规范的增强载具交接并行 I/O 接口，其信号必须遵循下述已定义的时序。载具交接时序的时序图见图 10–图 20。

#### 6.2.2 单次交接时序（装载/卸载）

**6.2.2.1** 单次交接中装载与卸载操作的时序图分别见图 10 与图 11。图 10、图 11 所示的时序如下：

**1)** 主动设备（AMHS 设备）到达载口前方的交接位置后，主动设备通过 `CS_0` 与 `CS_1` 指明它要向被动设备交接载具的载口编号。

**2)** 主动设备将 `VALID` 信号置 ON，表示 `CS_0`、`CS_1` 的信号跳变**有效**。

> **注 3**：被动设备在主动设备将 `VALID` 置 ON（即表明接口通信有效）之前，不应去校验 `CS_0` 或 `CS_1` 是否为 ON。

**3)** 若载口已准备好执行**装载**操作，被动设备将 `L_REQ` 信号置 ON；若载口已准备好执行**卸载**操作，则置 `U_REQ` 为 ON。

**4)** 为请求被动设备启动载具交接操作，主动设备将 `TR_REQ` 信号置 ON。

**5)** 当被动设备准备好交接载具时，它将 `READY` 信号置 ON。

**6)** 主动设备确认 `READY` 为 ON 后，将 `BUSY` 信号置 ON，并开始交接动作。

**7)** 当载具被正确放置到载口上（或载口上的载具被取走）时，被动设备将 `L_REQ`（`U_REQ`）信号置 OFF。

**8)** 装载或卸载动作完成、且主动设备的运动机构已退出交接干涉区之后，主动设备将 `BUSY` 置 OFF。**主动设备必须在 `BUSY` 置 OFF 之前确认 `L_REQ`（`U_REQ`）已为 OFF。**

**9)** 主动设备在 `BUSY` 置 OFF 的同时将 `TR_REQ` 置 OFF。

**10)** 主动设备将 `COMPT` 信号置 ON，通知被动设备交接操作已完成。

> **注 4**：若被动设备要校验 `BUSY` 与 `TR_REQ` 是否为 OFF，它应当只在主动设备已将 `COMPT` 置 ON（表明主动设备已完成交接）**之后**才去校验这两个信号。

**11)** 确认主动设备已把 `COMPT` 置 ON 之后，被动设备将 `READY` 信号置 OFF。

**12)** `READY` 置 OFF 之后，主动设备将 `COMPT`、`VALID`、`CS_0`、`CS_1` 信号全部置 OFF。

**13)** 当 `VALID` 信号被置 OFF 时，与被动设备的握手**闭合**（本次交接结束）。

> **注 5**：若被动设备要检查 `COMPT`、`VALID` 以及 `CS_0` 或 `CS_1` 信号，它应允许这些信号以**任意顺序**置 OFF，而不因此报错。

#### 6.2.2.2 OHS（跨区被动型车辆）与储料机之间的单次交接时序

本节定义 OHS（跨区被动型车辆）与储料机（Stocker）之间的单次交接时序。单次交接中装载与卸载操作的时序图分别见图 12 与图 13。图 12、图 13 所示的时序如下：

**1)** 当被动设备（即 OHS）到达主动设备（即储料机）处时，被动设备通过 `VS_0` 与 `VS_1` 向主动设备指明交接将在何处进行。

**2)** 在 `VS` 置位的同时，若载口准备好执行**装载**操作，被动设备将 `L_REQ` 信号置 ON；若载口准备好执行**卸载**操作，则置 `U_REQ` 为 ON。

**3)** 被动设备将 `VA` 信号置 ON，表示 `VS_0`、`VS_1` 以及 `L_REQ` 或 `U_REQ` 的信号跳变**有效**。

**4)** 主动设备识别到 `VA` 信号后，检查 `VS_0`、`VS_1`、`L_REQ` 与 `U_REQ` 信号，并将 `TR_REQ` 信号置 ON，请求被动设备启动载具交接操作。

**5)** 当被动设备准备好交接载具时，它将 `READY` 信号置 ON。

**6)** 主动设备确认 `READY` 为 ON 后，将 `BUSY` 信号置 ON，并开始交接动作。

**7)** 当载具被正确放置到载口上（或载口上的载具被取走）时，被动设备将 `L_REQ`（`U_REQ`）信号置 OFF。

**8)** 装载或卸载动作完成、且主动设备已退出交接干涉区之后，主动设备将 `BUSY` 置 OFF。主动设备必须在 `BUSY` 置 OFF 之前确认 `L_REQ`（`U_REQ`）已为 OFF。

**9)** 主动设备在 `BUSY` 置 OFF 的同时将 `TR_REQ` 置 OFF。

**10)** 主动设备将 `COMPT` 信号置 ON，通知被动设备交接操作已完成。

**11)** 确认主动设备已把 `COMPT` 置 ON 之后，被动设备将 `READY` 信号置 OFF。

**12)** `READY` 置 OFF 之后，主动设备将 `COMPT` 置 OFF。

**13)** 确认主动设备已将 `COMPT` 置 OFF 之后，被动设备将 `VS_0`、`VS_1` 与 `VA` 置 OFF。

**14)** 当 `VA` 信号被置 OFF 时，与被动设备的握手闭合。

#### 6.2.3 同时交接时序（装载）

**6.2.3.1** 本规范定义了控制同时交接的能力。**同时交接**是指主动设备在一次传输动作中把两个载具同时送到两个载口上的交接操作。某些类型的 AMHS 设备能够在一次传输动作中同时搬运两个载具。该能力可用于提升传输性能。例如，同时交接可应用于单臂双手、能够在一次传输动作中搬运两个载具的 AMHS 设备。

**6.2.3.2** 同时交接的时序图见图 14。该图只示出**装载**操作；对于卸载操作，可将 `L_REQ` 替换为 `U_REQ`。同时交接的时序与单次交接相同，只是**用 `CS_0` 与 `CS_1` 指定载口的方式**、以及 **`L_REQ`/`U_REQ` 的 ON/OFF 定义**有所不同。与图 10、图 11 不同之处如下：

**1)** 主动设备将 `CS_0` 与 `CS_1` 信号**同时置 ON**，告知被动设备这是一次同时交接。

**2)** 在 `CS_0` 与 `CS_1` 的跳变生效之后，主动设备将 `VALID` 信号置 ON。

**3)** 当指定的两个载口（`CS_0` 与 `CS_1` 对应的载口）上的两个载具都已准备好被装载（或被卸载）时，被动设备将 `L_REQ`（`U_REQ`）信号置 ON。

**4)** 当两个载口上都检测到载具（或两个载口上的载具都被取走）时，`L_REQ`（`U_REQ`）信号被置 OFF。

**6.2.3.3** 本规范定义了控制同时交接的能力。同时交接是指主动设备在一次传输动作中把两个载具同时送到两个载口上的交接操作。某些类型的跨区 AMHS 设备（即储料机）能够在一次传输动作中同时搬运两个载具。该能力可用于提升传输性能。例如，同时交接可应用于单臂双手、能够在一次传输动作中搬运两个载具的 AMHS 设备。

#### 6.2.4 连续交接时序

**6.2.4.1** 本规范定义了控制连续交接的能力。**连续交接**是指主动设备在一次载具传输动作中，依次、连续地搬运两个或更多载具的交接操作。某些类型的 AMHS 设备能够在一次传输动作中交接两个以上的载具。该能力可用于提升传输性能。

**6.2.4.2** 当被动设备在载口前方装有闸门时，该闸门必须在主动设备开始载具交接**之前**开启。当需要搬运两个或更多载具时，每个载具交接都开关一次闸门是多余的。因此，在载具传输操作期间闸门应**保持开启**。连续交接正是为了消除这类冗余动作而被用于传输操作的。

**6.2.4.3 在同一载口上连续交接的时序（卸载 → 装载）**：连续交接的示例时序图见图 16。该示例展示了在同一载口上连续执行的卸载与装载操作的时序。连续交接中的每一段时序都是单次交接时序的组合。此外，还要用 `CONT` 信号来指明这是一次连续交接。

在图 16 所示的时序中，先卸载载口上的载具，再向该载口装载一个新载具。`CONT` 信号在**第一次**交接的主动设备 `BUSY` 置 ON 时被置 ON，以表明交接是连续的。在后续的装载时序中，**指定同一个载口编号**（本例中为 `CS_0`）以使用同一个载口。在本例中，第二次装载时序之后不再有需要搬运的载具，因此主动设备在第二次交接的 `BUSY` 信号置 ON 时**将 `CONT` 置 OFF**，表明连续交接已完成。

#### 6.2.5 可交接信号时序（`HO_AVBL`）

**6.2.5.1** `HO_AVBL` 信号的示例时序图见图 18 与图 19。`HO_AVBL` 信号在被动设备正常运行期间为 ON；当被动设备检测到任何与交接相关的异常时，应将其置 OFF。主动设备通过 `HO_AVBL` 信号获知异常状况。主动设备应在以下时段内确认 `HO_AVBL` 信号：

- **a)** 从 `VALID` 信号被置 ON 起，到 `L_REQ` 或 `U_REQ` 信号被置 ON 止；
- **b)** 从 `TR_REQ` 信号被置 ON 起，到 `READY` 信号被置 ON 止。

**6.2.5.2** 图 18 是解释上述情况 **a)** 的时序图。当主动设备检测到被动设备把 `HO_AVBL` 置 OFF 时，它**停止**交接操作，并把 `VALID` 信号置 OFF 以闭合握手（此时 `CS_0` 与 `CS_1` 信号必须置 OFF）。被动设备在 `VALID` 信号被置 OFF **之后**，才把 `HO_AVBL` 信号重新置 ON（此时 `L_REQ` 或 `U_REQ` 必须已置 OFF）。

**6.2.5.3** 图 19 是解释上述情况 **b)** 的时序图。当主动设备检测到被动设备把 `HO_AVBL` 置 OFF 时，它停止交接操作，并把 `VALID` 信号置 OFF 以闭合握手（此时 `CS_0`、`CS_1` 与 `TR_REQ` 信号必须置 OFF）。被动设备在 `VALID` 信号被置 OFF **之后**，才把 `HO_AVBL` 信号重新置 ON（此时 `L_REQ` 或 `U_REQ` 必须已置 OFF）。

**6.2.6.1** `HO_AVBL` 信号的示例时序图见图 18 与图 19。`HO_AVBL` 信号在被动 OHS 正常运行期间为 ON；当被动 OHS 检测到任何与交接相关的异常时，应将其置 OFF。主动储料机通过 `HO_AVBL` 信号获知异常状况。主动储料机应在以下时段内确认 `HO_AVBL` 信号：

### 6.3 错误指示、检测与恢复

#### 6.3.1 错误指示

**6.3.1.1** 为支撑运行可靠性，本规范定义了以下在接口上指示错误的能力：

**a)** 通知**交接不可用**——即被动设备（或被动 OHS）不能向主动设备提供物料交接操作；
**b)** 通知**紧急停止请求**给主动设备（或主动储料机）；
**c)** 通知**交接超时错误**。

#### 6.3.2 错误检测

**6.3.2.1** 要用**互锁超时**（interlock timeout）来检测主动设备与被动设备之间的交接时序错误。本规范定义了主动设备与被动设备各自应监视的互锁超时。表 5 给出主动设备的互锁超时，表 6 给出被动设备的互锁超时。

`TAx`（x 为数字）表示主动设备的定时器，`TPx`（x 为数字）表示被动设备的定时器。**除 `TD0` 之外**，所有定时器的取值范围均为 **1 秒到 999 秒**。所有定时器的设定值都应**可由用户编程**。

#### 表 5　主动设备定时器

| 定时器名 | 监视的时段（信号状态） | 范围（秒） | 典型值 TYP（秒） |
|---|---|---|---|
| `TA1` | `VALID` ON — `L_REQ` ON<br>`VALID` ON — `U_REQ` ON | 1–999 | 2 |
| `TA2` | `TR_REQ` ON — `READY` ON | 1–999 | 2 |
| `TA3` | `COMPT` ON — `READY` OFF | 1–999 | 2 |

> **注 1**：定时器的最小值**并不**定义主动设备的响应时间。
> **注 2**：这些定时器值必须被实现以用于检测超时，而**不是**用来规定信号之间的延时时间。设备响应时间必须快于该定时器的超时时间。

#### 表 6　被动设备定时器

| 定时器名 | 监视的时段（信号状态） | 范围（秒） | 典型值 TYP（秒） |
|---|---|---|---|
| `TP1` | `L_REQ` ON — `TR_REQ` ON<br>`U_REQ` ON — `TR_REQ` ON | 1–999 | 2 |
| `TP2` | `READY` ON — `BUSY` ON | 1–999 | 2 |
| `TP3` | `BUSY` ON — 检测到载具（CARRIER DETECT）<br>`BUSY` ON — 载具被取走（CARRIER REMOVE） | 1–999 | **60** |
| `TP4` | `U_REQ` OFF — `BUSY` OFF<br>`L_REQ` OFF — `BUSY` OFF | 1–999 | **60** |

> **注 1**：定时器的最小值**并不**定义被动设备的响应时间。
> **注 2**：这些定时器值必须被实现以用于检测超时，而**不是**用来规定信号之间的延时时间。设备响应时间必须快于该定时器的超时时间。

**6.3.2.2** **延时定时器**规定了两次相继交接的 `VALID` 信号之间的延迟时间。之所以需要延时定时器，是因为被动设备可能需要一定的时间余量来检测第二次 `VALID` 信号的 ON 跳变。表 7 给出延时定时器。所有定时器的设定值都应可由用户编程。

**6.3.2.3** 推荐且可选的延时定时器 `TD0` 定义了主动设备从 `CS_0` 或 `CS_1` 置 ON 到 `VALID` 置 ON 之间的时序，如各信号时序图所示。这样一来，被动设备就能**预测**主动设备将输出信号的时间点，从而使传输互锁得以精确执行。

#### 表 7　延时定时器

| 定时器名 | 监视的时段（信号状态） | 范围（秒） | 典型值 TYP（秒） |
|---|---|---|---|
| `TD0` | `CS` ON — `VALID` ON | 0.1–0.2 | 0.1 |
| `TD1` | `VALID` OFF — `VALID` ON | 1–999 | 1 |

> ※ 译者注：这 11 个定时器是 E84 实现里最容易做、也最容易被忽略的部分。要点有三：
> 1. **`TP3`/`TP4` 的典型值是 60 s，而不是 2 s**——因为这两段要等待机械动作（放料/取料、机械手退出干涉区）完成，属于"慢动作"，其余定时器监视的都是控制器之间的电信号往返，典型值 2 s。
> 2. **`TD0`（0.1 s）是所有定时器里唯一以 0.1 s 为量级的**，它规范的是"选口 → 抬 `VALID`"之间的固定间隔。有了它，被动设备可以在 `CS` 变化后**恰好在 0.1 s 时**去采样 `VALID`，实现精确的传输互锁——这是 E84 里一个很讲究的设计细节。
> 3. 这些定时器**全部要可现场配置**。超时值定得太紧，会在设备响应稍慢时误报互锁异常；定得太松，会在真出问题时迟迟不报。

#### 6.3.3 错误恢复

**6.3.3.1** 本规范**不定义**错误恢复流程。恢复流程可能需要操作员介入，和/或设备专有的私有流程。建议在主动设备与被动设备上都提供恢复流程（例如：中止互锁时序，并设置重启/完成）。

> ※ 译者注：标准明确"不管"恢复，意味着**这一块必须由设备厂商自行定义并写入规格书**。实践中最常见的做法是提供两个复位语义：**中止（abort/clear）** 与 **重试（restart）**，且两侧都要能独立发起。参见「相关信息 1」中的错误场景与建议对策。

**A1-4** 设备分为两类：**内部缓存型（internal buffer）**设备与**固定缓存型（fixed buffer）**设备。内部缓存型设备是指**在设备内部使用载口（load port）以外的位置来存放载具**的设备。固定缓存型设备是指**只有固定载口、没有用于载具存放的内部缓存**的生产设备，晶圆直接在载口处从载具中装载和卸载以进行处理。

**A1-5** 本标准规定了两种不同的 PI/O 配置：**每个载口一个 PI/O**，以及**每两个载口一个 PI/O**（图 A1-2）。如果能够**同时**传输一个以上的载具，则载具传输的吞吐量与效率更高。如果厂内 AMHS（intrabay AMHS）设备能够从**同一个停靠位置**同时输送两个或更多载具，则载具传输时间也能缩短。通常，允许向两个载口**同时或连续**交接两个载具的内部缓存型设备，最能利用这些吞吐量的改善。

> 1. **出错时出错方要"钉住" `BUSY`（保持 ON）**。这是全篇最重要的一条安全设计意图：`BUSY` 保持 ON 等于向对方宣告"我出问题了，别自己动"，从而**防止对方自主动作造成二次事故**。
> 2. **`READY` 一律拉 OFF**——因为"准备好"已经不成立了；而在**被动侧**出错时还要额外拉掉 `ES`（停止请求）和 `HO_AVBL`（交接可用），即**宣告整个交接点不可用**。
> 3. **恢复的判据是"载具落在谁手里"**，而不是"操作到哪一步"：载具退回到**发起方自己**手里（场景 2、3）→ 序列**从头重做**；载具退回到**对方**手里（场景 1、4）→ **本次操作视为已完成**（因为交接的物理目标其实已经达成了）。这一条判断错了，就会造成同一载具被重复搬运或载具丢失。

如果储料机是跨区 AMHS（即 OHS 与储料机）的**主动侧**，则可以想见：在故障场景下，装载机（loader）**可能会干扰经过储料机的 OHS**。鉴于这种可能性，跨区 AMHS 设备制造商有必要**在 SEMI E84 互锁之外另行设置一个 OHS "PASS OK" 信号**。但本注与 SEMI E84 的内容**没有直接关系**，因此 SEMI E84 的读者**只应将其作为参考条目**看待。

#### 通过互锁（Pass Interlock）

#### 互锁信号

| 信号名 | P/A | 描述 |
|---|---|---|
| `PASS OK` | A → P | 当该信号为 HIGH（ON）时，车辆（vehicle）**可以**通过。当该信号为 LOW（OFF）时，车辆**不得**通过。 |

> ※ 译者注：这一条讲的是一个**标准覆盖不到的场外风险**：当储料机是主动方时，它的装载机械手/缓存位可能与正在通过（pass by）的 OHS 车辆发生空间冲突。E84 的互锁只管"交接这一刻"，管不了"路过这一刻"，所以需要厂商**额外**加一个 `PASS OK` 信号做通过许可。注意它**不属于 E84**，接线和针脚也**不在表 9 之列**，需要自行规划（表 9 中的 Reserved 引脚正是为这类扩展预留的）。

## 相关信息 3（RELATED INFORMATION 3）

> **注**：本相关信息**不是 SEMI E84 的正式组成部分**，而是源自 E84 任务组（E84 Task Force）的工作成果。本相关信息经委员会于 **2000 年 10 月 19 日**投票批准发布。

**R3-1** E84 任务组在 2000 年 10 月投票的 E84 条目变更集中，**无意中遗漏了**随附的信息与定义。为帮助澄清标准，SEMI 物理接口与载具委员会（SEMI Physical Interfaces and Carriers Committee）于 2000 年 10 月 19 日批准增补本相关信息。E84 任务组计划在下一个投票周期将这些定义提交投票，以纳入 E84 标准。

### R3-1.1　在以下术语中增加带下划线的文字

**access mode（访问模式）** —— 一种模式，在该模式下被动设备**知道**哪一台 AMHS 设备（即 RGV、AGV 和 OHT/OHV）或操作员被**允许**进行物料交接。就跨区 AMHS 而言，这是一种被动设备知道哪台 AMHS 设备（即 OHS 以及配备传输装置的储料机）被允许进行物料交接的模式。

**automated material handling system (AMHS) equipment（自动物料搬运系统设备）** —— 一台具有载具传输机器人、可在被动设备之间往返传输载具的设备。它包括有轨制导车辆（RGV）、自动导引车（AGV）、空中吊车输送车（OHT）、空中穿梭车（OHS）以及储料机（stockers）。

### R3-1.2　增加以下术语

**active vehicle（主动车辆）** —— 一台**装有**可将载具从一台设备装载/卸载到另一台设备的装置的主动型 OHS 车辆。

**passive vehicle（被动车辆）** —— 一台**未装有**可将载具从一台设备装载/卸载到另一台设备的装置的主动型 OHS 车辆。

> ※ 译者注：R3-1.1 里的 `access mode` 是理解 E84 与上层调度（MES/AMHS 控制器）接口的关键概念——它解释了一个物理交接点如何**通过配置限定"谁有资格来交接"**（例如某个载口只允许指定的那台 OHT 或某个操作员），这也是 §5 术语中"被动设备"概念的延伸。
>
> 另需注意原文一处**明显的笔误**：`passive vehicle` 的定义写成 "An **active** OHS vehicle that does not contain a device…"，按上下文应为 "An **OHS** vehicle that does not contain…"（被动车辆本身不应是主动型）。本译文按原文直译并在此标注，实际引用时请以上下文逻辑为准。
